# Phase 5 - 工具详情与配置中心化

状态: pending
仓库: D:\Repos\kuncode-setup
依赖: Phase 3

## 背景

目前「配置」只有一次性向导：配置完成后，用户想换模型、看当前用的是哪把密钥、
看程序到底改了哪些文件，都只能重跑整条向导或去翻配置文件。
对比 CCS 这类工具，缺少一个「管理已配置工具」的详情页。

本阶段把「已配置工具」变成可查看、可管理的对象，并补齐几个低成本高感知的
体验项。不引入本地代理、协议转换、Header/Body 覆盖等高级能力——那与
「面向小白、直连站点」的定位冲突。

## 目标

让已配置的工具有一个可查看、可管理的详情页，并补齐连接测速、配置查看等
日常运维能力。

## 交付项

- [ ] 工具详情页：展示当前绑定的密钥、分组、模型列表、配置路径与状态；
      提供换模型 / 换绑密钥 / 恢复备份 / 重新配置入口
- [ ] 查看实际写入的配置：展示脱敏后的 config.toml / settings.json（只读），
      让用户知道程序改了什么
- [ ] 连接测速：复用 probe_binding 的延迟，给连接/密钥标注延迟；
      支持「自动选择最快连接」
- [ ] 连接备注与别名：为每个站点连接设置可编辑别名与备注，列表更可读
- [ ] 密钥一键复制：密钥中心提供「复制密钥」按钮（走 reveal 接口，
      仅内存中转，不写入日志）

## 设计要点

- 详情页路由建议 /tools/:agent（与 /setup/:agent 向导区分开）
- 展示配置内容必须脱敏：API Key / token 一律掩码，不返回明文
- 密钥复制只写系统剪贴板，前端不持久化明文
- 测速失败不阻断使用，仅标注「未测速」

## 验收

- 已配置的工具能在一个页面看到「用了哪把密钥、哪些模型、改了哪些文件」
- 能直接在该页面换模型 / 换绑密钥，无需重跑整条向导
- 连接列表能看到延迟；密钥可一键复制
